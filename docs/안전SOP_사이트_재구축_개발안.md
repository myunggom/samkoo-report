## 2. 문제별 해법

### 2.1 사진을 일일이 확인·수정하는 문제

**원인** — 사진 1,702장과 설명이 사람 손으로 짝지어져 있다. 틀린 것을 찾으려면 전부 눈으로 봐야 한다.

**해법 — 사람이 보는 양을 줄인다**

1. **AI 1차 검수 (전수)** — 생성된 사진마다 Gemini 에게 사진과 설명을 같이 주고 판정시킨다.
   - 설명과 사진 내용이 맞는가
   - 지정된 보호구를 실제로 착용했는가
   - 손가락·팔 개수, 얼굴 왜곡, 글자 깨짐이 없는가
   - 동일 인물인가
2. **불합격만 보는 검수 화면** — 사진·설명·불합격 사유를 한 화면에 띄우고 `승인 / 다시 생성 / 설명 수정` 세 버튼. 키보드로 넘긴다.
3. **재생성은 버튼 하나** — 사유가 프롬프트에 자동 반영된다.

전수 검수에서 보통 10~20%가 걸리므로, 사장이 볼 양은 **200~300장**으로 줄어든다.

### 2.2 작업별 보호구 자동 산출

**원인** — 보호구를 작업마다 사람이 골라 넣는다. 그래서 복사로 다 같아지고, 모순(고무장갑 자리에 절연장갑)과 누락(고소작업인데 안전대 없음)이 생긴다.

**해법 — 보호구 규칙 엔진**

입력은 이미 `data.js` 에 다 있다. 작업명 · 작업 내용 · 장비 · 조치사항 문구에서 **위험요인**을 뽑고, 위험요인에서 보호구를 끌어낸다.

| 위험요인 (자동 판별 단서) | 필수 보호구 |
|---|---|
| 고소작업 · 2m 이상 · 사다리 · 비계 · 고소작업대 | 안전대(턱끈 체결 안전모 포함), 추락방지대 |
| 활선 · 충전부 · 수전 · 배전반 · MCC | 절연장갑, 절연화, 아크 보호면, 방염복 |
| 물 · 약품 · 세정 · 수조 · 배수 | 고무장갑, 장화, 보안경 |
| 용접 · 화기 · 그라인더 | 차광보안면, 가죽장갑, 방진마스크, 방염복 |
| 밀폐공간 · 맨홀 · 피트 | 송기마스크 또는 공기호흡기, 가스검지기, 구명줄 |
| 소음 90dB 이상 · 송풍기실 | 귀마개 |
| 분진 · 석면 · 그라인딩 | 방진마스크, 보안경 |
| 화학물질 · 약품 주입 | 방독마스크, 내화학 보호장갑, 보안경 |

**3단 판정으로 내놓는다**

- **필수** — 규칙상 반드시 있어야 하는 것
- **권장** — 상황에 따라 필요한 것
- **모순 경고** — 예: 활선작업이 아닌데 절연장갑 / 물 작업인데 절연장갑(→ 고무장갑) / 안전대 없는 고소작업

**사장이 하는 일은 승인뿐이다.** 수정하면 그 작업만 고정(override)되고 다음에 규칙이 바뀌어도 유지된다.

**사진 요청 목록 자동 생성** — 보호구 54종 중 예시 사진이 없는 것을 뽑아 목록으로 띄운다. 사장은 그 목록만 보고 사진을 주면 된다.

### 2.3 지식재산권

**방향 — 표현을 바꾸는 것이 아니라 근거를 바꾼다.**

표현만 다듬는 것은 해결이 아니다. 근거 자료를 바꿔서 다시 쓰면 순서와 내용이 자연히 달라지고, 출처를 댈 수 있게 된다.

**1차 근거로 쓸 것**

- 산업안전보건법 · 시행령 · 시행규칙 · 산업안전보건기준에 관한 규칙
- KOSHA GUIDE (안전보건공단 기술지침)
- 설비 제조사 취급설명서 · 점검 주기표
- **우리 건물의 실제 설비 구성과 동선** ← 이것이 가장 강력하다

작업 순서를 우리 건물 기준으로 다시 쓰면 타사 자료와 같아질 수 없다. 지금도 `data.js` 에 실제 분전반 이름(`LN GY B3A` 등)과 층별 위치가 들어 있으므로 이를 기준으로 재구성한다.

**조치사항마다 근거를 표기한다** — 예: `산업안전보건기준에 관한 규칙 제32조(보호구의 지급 등)`, `KOSHA GUIDE E-xx-xxxx`. 출처가 붙으면 분쟁 여지가 줄고 교육자료로서 신뢰도도 올라간다.

**솔직히 말씀드릴 부분** — 실질적으로 복제된 문단이 있다면 표현을 바꾸는 것으로는 해결되지 않는다. 해당 부분은 **교체**가 안전하고, 범위가 넓다면 법률 검토를 받는 편이 낫다. 어느 부분이 어느 자료에서 왔는지 사장이 알고 있는 만큼, 먼저 **그 목록을 주시면** 우선순위를 그쪽에 둔다.

**작업량** — 대상은 조치사항 1,332건. AI가 근거를 붙여 초안을 쓰고 사장이 검수한다. 부문별(공통·건축·전기·기계·소방·미화·보안)로 나눠 진행한다.

### 2.4 사진 생성 자동화 ← 핵심

#### 원인을 찾았습니다

현재 참조 이미지는 **`표준인물.png` 한 장**뿐이다.

Gemini 이미지 생성 API는 **인물 참조를 4~5장**, 총 **14장**까지 받는다. 한 장만 주면 얼굴이 고정되지 않는다. 그래서 마스크로 가렸고, 경영진이 반대하게 된 것이다. **원인이 마스크가 아니라 참조 장수였다.**

그리고 지금 도구는 참조 폴더에 있는 **9장을 작업과 무관하게 전부** 넣는다. 관계없는 참조가 섞이면 품질이 떨어진다.

#### 해법 네 가지

**① 캐릭터 시트 — 인물 참조 5장**

표준인물을 **정면 / 좌 3-4 / 우 3-4 / 상반신 / 전신** 5장으로 한 번 만들고 사장이 승인한다. 이 5장을 모든 생성에 인물 참조로 첨부한다. **마스크를 벗겨도 얼굴이 유지된다.**

**② 참조 14장 운용 규칙**

| 구분 | 장수 | 내용 |
|---|---:|---|
| 인물 | 5 | 캐릭터 시트 (고정) |
| 물체 | 6~8 | **그 작업에 필요한 보호구·장비만** 선택 |
| 합계 | ≤ 14 | 모델 한도 |

보호구는 2.2 규칙 엔진이 이미 작업별로 정하므로, 그 결과를 그대로 참조 선택에 쓴다.

**③ 자동 검수 루프 — 사람 5명을 대체하는 부분**

```
프롬프트 생성 → 이미지 생성 → Gemini 판정 → 불합격이면 사유를 붙여 재생성 (최대 3회)
                                   ↓ 3회 실패
                              사람 검수 목록으로
```

판정 항목 : 동일 인물 / 손·팔 개수 / 얼굴 왜곡 / 지정 보호구 착용 / 글자 깨짐 / 해상도

지금 사람 5명이 하던 "추려내는 일"이 바로 이 판정이다. 기계가 하면 밤새 돌아간다.

**④ 모델과 비용**

권장 모델은 **`gemini-nano-banana-2.1`** (현재 도구가 이미 쓰고 있다).

| | 1장 | 1,702장 전량 |
|---|---:|---:|
| 일반 호출 1K | 약 $0.034 | 약 $58 (8만원) |
| 배치 호출 1K | 약 $0.017 | 약 $29 (4만원) |

자동 검수로 재생성이 2배 발생해도 **20~30만원 수준**이다. 사람 5명이 몇 주 붙는 것과 비교할 수준이 아니다. 4K가 필요하면 장당 약 $0.076 로 올라가므로, 웹 표시 크기에 맞춰 1K~2K 로 유지한다.

> 가격은 출처마다 차이가 있어 **실제 집행 전 구글 공식 가격표로 재확인**한다. 그리고 유료 호출이므로 **전량 재생성은 사장 승인 후** 실행한다.

**⑤ Gemini CLI 와 API 중 무엇을 쓸 것인가 → API**

CLI 는 대화형이라 1,702장 배치에 맞지 않는다. 이미 `sop_generate_images.py` 가 API 로 연결되어 있고 건너뛰기·재시도·해상도 검사까지 되어 있으므로, **API 를 유지하고 다음 두 가지만 추가**한다.

- 인물 참조 다중화 (1장 → 5장) + 작업별 물체 참조 선택
- 자동 검수 루프

### 2.5 로그인 · 권한

**권한 3단**

| 권한 | 할 수 있는 것 |
|---|---|
| 마스터 | 가입 승인, **아이디 사용 정지**, 권한 변경, 접속 기록 열람, 모든 편집 |
| 편집자 | 작업·사진·교육자료 편집 |
| 열람자 | 보기만 |

**마스터 기능**

- 가입은 **승인제** — 현장 교육자료이므로 아무나 가입하면 안 된다
- **아이디 정지** — 삭제가 아니라 정지. 누가 언제 무엇을 고쳤는지 기록이 남아야 하므로 계정을 지우지 않는다
- 접속·편집 기록 열람

**전제 — Next.js 로 옮겨야 한다**

지금 `sop/` 는 정적 HTML 이라 로그인을 붙일 서버가 없다. 이미 쓰고 계신 `report/`(samkoo-report)와 같은 Next.js 구조로 옮기면 로그인·권한·편집 저장이 모두 해결되고, Blob 저장과 배포 방식도 그대로 쓸 수 있다.

**확인 필요** — 현장 QR 로 들어오는 작업자도 로그인을 해야 하나? 현장에서 바로 봐야 하는 자료이므로 **QR 접속은 로그인 없이 열람만** 가능하게 하는 쪽을 권한다.

## 4. 단계

| 단계 | 내용 | 효과 | 선행 조건 |
|---|---|---|---|
| **1** | 캐릭터 시트 5장 + 참조 선택 + 자동 검수 루프 | 사진 문제 해결, 마스크 제거 | 표준인물 확정, API 예산 승인 |
| **2** | 보호구 규칙 엔진 + 사진 요청 목록 | 보호구 모순·누락 해소 | 1단계 |
| **3** | Next.js 이전 + 로그인·권한 | 자료 통제 | 2단계 |
| **4** | 교육자료 근거 기반 재작성 | 지식재산권 정리 | 유사 우려 부분 목록 |
| **5** | 디자인 재구축 | 가독성 | 3단계 |

1단계가 가장 급하고 효과가 크다. 2단계는 1단계의 참조 선택에 바로 쓰인다. 4단계는 양이 많아 부문별로 나눠 1~3단계와 병행할 수 있다.

## 5. 결정해 주실 것

1. **표준인물** — 지금 인물을 유지할지, 마스크 없는 얼굴로 새로 만들지
2. **QR 접속자 로그인** — 필요한지, 열람만 열어둘지
3. **지식재산권 재작성 범위** — 조치사항 1,332건 전체인지, 유사 우려 부분만인지 (후자면 그 목록 필요)
4. **1단계 사진 재생성 예산** — 유료 API. 전량 약 20~30만원 예상
5. **개발 PC** — 웹 작업은 다른 PC 에서 하고 계시니, 어느 쪽에서 진행할지
