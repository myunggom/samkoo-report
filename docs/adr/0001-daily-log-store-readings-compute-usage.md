# ADR-0001: 일일 업무일지는 날짜별 기록 1건, 계량은 지침만 저장하고 사용량·누계는 계산

**Date**: 2026-09-29
**Status**: accepted
**Deciders**: 운영자, Claude

## Context

고객사 일일 업무일지를 엑셀로 쓰면서 근무일마다 시트를 복사했다(9월에만 19장). 전일검침은 전날 시트에서 손으로 옮겨 적었고, 월 누계는 `='09.28'!K30+I30` 처럼 전날 시트에 줄줄이 이어 붙였다. 하루를 빠뜨리거나 시트 이름을 틀리면 그 뒤 누계가 전부 틀어지고, 월초마다 연결을 새로 해야 했다.

## Decision

`/daily-log` 탭에서 하루를 `DailyLog` 한 건(날짜·인원·구분별 업무·특이사항·계량 지침)으로 저장한다. 계량은 **금일 지침만** 저장하고, 전일검침·사용량(전력 배율 3600)·월 누계는 `lib/dailyLog.ts` 순수 함수가 매번 계산한다. 새 날짜는 가장 최근 일지의 명일 계획·비고·인원을 미리 채운다.

## Alternatives Considered

### Alternative 1: 엑셀 유지 + 입력 시트 3장·보고 시트 1장으로 개편
- **Pros**: 회사 PC에서 설치 없이 동작, 수식으로 같은 계산 가능 (실제로 만들어 399칸 일치 검증)
- **Cons**: 현장(폰)에서 입력 불가, PDF 저장·파일 전달이 수작업
- **Why not**: 백업용으로는 유지하되, 매일 쓰는 도구로는 웹이 입력 부담이 적다

### Alternative 2: 사용량·월 누계도 저장
- **Pros**: 조회가 단순
- **Cons**: 과거 지침을 고치면 그 뒤 누계가 모두 틀어진 채 남는다 — 엑셀과 같은 문제
- **Why not**: 1년 약 250건이라 매번 계산해도 비용이 없다

## Consequences

### Positive
- 날짜가 빠지거나 과거 값을 고쳐도 누계가 자동으로 맞는다
- 지침 역전(음수)·평소 3배 사용량을 입력 즉시 경고

### Negative
- 화면이 전체 기록을 한 번에 불러온다 (규모가 커지면 월 단위 조회로 바꿀 것)

### Risks
- 월 첫 기록의 전일검침은 전월 마지막 지침이 있어야 나온다 → 이관 시 전월 말 지침 한 줄(8/31)을 함께 넣었다
- 계산 규칙 검증: `lib/dailyLog.check.mts`(가짜 값). 실데이터 검증(9월 399칸 일치)은 공개 저장소라 코드에 넣지 않았다
